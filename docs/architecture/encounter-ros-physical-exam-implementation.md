# Synthetic ROS and examination implementation

Implemented 2026-10-22 for the opt-in local synthetic clinical slice. The companion [clinical review packet](encounter-ros-physical-exam-clinical-review.md) remains unapproved. No real-patient use is enabled.

## Behavior

- All six synthetic encounter types have v1.2.0 immutable releases with template-driven ROS and physical-examination findings. The original v1.0.0 and narrative v1.1.0 JSON bytes are retained under `api/src/main/resources/encounter-templates/synthetic/v1/` and `v1.1/`. Seeding publishes all three version-specific releases, then retires v1.0.0 and v1.1.0 site availability for new starts. Pinned encounters and archived signed bytes remain readable. Repeated seeding leaves releases and explicit v1.2.0 site retirement intact.
- Gynecology's existing restricted examination and consent/chaperone fields appear in the new examination section with unchanged field IDs and sensitivity. The specialty field is labeled distinctly from the common examination narrative.
- The dynamic editor reads `quickFindings` from each pinned ROS/examination field. Its compact system rows show only selected phrases or clinician-written findings as recorded; untouched rows stay "Not recorded" and are absent from the signed note. Each row expands for phrase selection and a custom finding. A whole-section narrative remains an alternative. Switching modes or replacing content with an explicit assessment state requires confirmation. There are no default negative/normal findings or copied-forward examinations. Existing debounced draft persistence, retry keys, conflict handling and navigation guards still apply.
- `quickFindings` is bounded, non-executable release metadata in the Java compiler, published JSON Schema, OpenAPI, generated TypeScript and runtime parser. `Answer.Value.findings` stores exact selected phrases and custom text with a system key; the server checks every phrase against the encounter's pinned release and renders the note in template system order. To change labels or phrases for future encounters, edit a source JSON definition, bump its business version, review the exact checksum and publish a new release. Existing releases are immutable. A visual template-authoring UI is not implemented.
- Fresh or changed direct clinician answers in any template field, including ROS/examination and explicit missing states, are marked reviewed in the server-saved revision under its authenticated actor. The generic form no longer asks for a source-review selection on each clinician-entered field. Reported/imported sources and older unreviewed entries still offer explicit review. Imported and unchanged answers do not inherit automatic review. The browser's review flag is not used as attribution evidence. Signing still validates required answers, source review and hidden-answer resolution, then binds exact archived HTML to the pinned release and response revision. The candidate displays the saved-revision actor.
- A sign validation error returns focus to the first missing or unreviewed field after the editor has re-enabled it. The signer still explicitly reviews the candidate and confirms the synthetic signature.

## Verification

Use `./api/mvnw -f api/pom.xml verify`, `npm --prefix web run lint`, `npm --prefix web run test`, and `npm --prefix web run build`. `TemplateEngineTests` checks all three versions, field compatibility, selected phrase validation and required value-or-state signing. `LocalSyntheticTemplatePackTests` checks idempotence, concurrent seed, site availability and rollback. `DirectFindingReviewTests` covers direct versus imported/unchanged review. `ConnectedEncounterTests` checks saved direct review, selected system rendering and exact candidate wording against PostgreSQL Testcontainers. Validate all eighteen JSON definitions against `api/contracts/template-definition-v1.schema.json`.

Rendered checks on the local synthetic site use 1440 × 1000 desktop, 834 × 1194 portrait tablet, and 390 × 844 mobile. The browser interaction check swaps a v1.2.0 catalog release into an existing v1.0.0 encounter response and intercepts draft requests in memory so it does not change the existing synthetic patient record. It verifies untouched rows, phrase selection for ROS and examination, simulated server-save confirmation, reload preservation, mode-switch warning/cancellation, console health, no horizontal overflow and screenshots. This browser simulation is UI evidence; persisted behavior is covered by the PostgreSQL tests.

## Remaining gates

The designated Practice clinical owner has not approved the six exact v1.2.0 release checksums, suggested phrases, permitted states or specialty overlap for real care. The current phrase lists are engineering fixtures, not clinical guidance; they contain no default selections. Reusable measurement extraction and an in-app visual template builder remain unimplemented. Clinician usability sessions for routine, complex, declined and teleconsultation cases, plus real-patient authorization, signing, privacy and restore gates, remain outstanding. The local signature adapter is synthetic development confirmation only.
